1. Executive Summary & Problem Statement

Digital authentication traditionally relies on software-generated pseudorandom tokens, pre-shared credentials, or biometric templates. CubeSec investigates a novel physical-digital hybrid architecture: sampling physical-world chaotic mechanical systems (a scrambled Rubik's Cube and the acoustic transients of its rotation) to create a physical context-binding and entropy-processing pipeline for secure authentication.

Prototype Cryptographic Scope: CubeSec is an exploratory research and hackathon prototype. Physical cube configurations and acoustic turn characteristics serve as demonstrative physical inputs, not certified True Random Number Generators (TRNGs). SHA-256 produces a deterministic digest, not an entropy amplifier. Security-critical session tokens are generated via the operating system's CSPRNG (Python secrets).

3. Module Specifications & Implementation Details

3.1 Module A: Cube Vision Engine (cv_analyzer.py)

The Cube Vision engine processes photographic inputs for the six canonical Rubik's cube faces (Up, Down, Front, Back, Left, Right). To avoid fabricated detections, images are first evaluated for sharpness using the Laplacian variance algorithm: 

Sharpness = Variance(Laplacian(GrayImage))

If the score is below 15.0, or average brightness is below 25.0 or above 245.0, the system rejects the image with an honest error. For valid images, the central 68% bounding area is sampled across a 3x3 grid (9 stickers per face, 54 stickers total). Colors are classified in HSV color space (Hue, Saturation, Value) into White (W), Yellow (Y), Green (G), Blue (B), Orange (O), and Red (R).

3.2 Module B: Entropy Engine & Feature Fusion (audio_analyzer.py)

The Entropy Engine processes mechanical turn sounds recorded live via browser MediaRecorder (synthesized to 16-bit PCM WAV) or uploaded audio files. Using NumPy, the system extracts:

  • RMS Signal Energy: Root Mean Square amplitude indicating mechanical turning power.
  • Zero-Crossing Rate (ZCR): Rate of signal sign alternations capturing sharp plastic impact transients.
  • Spectral Centroid (Hz): Frequency center of mass calculated via Real-FFT, reflecting click resonance.
  • Spectral Roll-off: The frequency boundary encompassing 85% of total signal power.

Visual and acoustic vectors are serialized into a canonical UTF-8 JSON structure with strict key ordering and hashed using standard SHA-256: 

{
  "domain_separator": "CubeSec-PhysicalEntropy-Context",
  "faces": { "U": "WGRBWYOYR", "D": "...", "F": "...", "B": "...", "L": "...", "R": "..." },
  "audio_descriptor": "SR:44100|DUR:2.800|RMS:0.05622|PEAK:0.8500|CENTROID:6228.3",
  "salt": "demo-context-salt-0x42"
}

3.3 Module C: Authentication Core (auth_core.py)

The Authentication Core separates physical context from security-critical randomness. Session tokens are generated via Python's standard secrets.token_urlsafe(32), yielding 256 bits of OS cryptographically secure randomness.

Tokens are stored in SQLite with an active Time-To-Live (TTL) countdown (60s, 180s, or 600s). The security gateway validates submitted tokens against tampering, expiration, and malformed prefixes.

5. Operational Scenarios & Threat Model

Threat Vector Vulnerability Analysis CubeSec Mitigation Strategy
Predictable Seed Cube faces can be observed or photographed by an attacker. Physical digest is never used as a secret key; tokens are generated via OS CSPRNG.
Acoustic Replay Adversary replays a recorded scramble sound. Multi-modal fusion binds 54 sticker states, acoustic telemetry, and an ephemeral salt.
Image Fabrication Submitting dark or blank images to exploit classification. Strict Laplacian variance (>= 15.0) and brightness thresholds enforce honest rejection.
Token Replay Valid token intercepted in transit. Strict configurable TTL expiration (e.g. 60–180s) automatically purges token validity.
