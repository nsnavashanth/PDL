CubeSec Authentication System

An exploratory security prototype investigating physical-world entropy acquisition. CubeSec connects computer vision cube face recognition, scramble audio acoustic feature extraction, canonical pre-image hashing, and secure token issuance.

Prototype Positioning: This local demonstration showcases a proposed physical-world authentication concept. Physical arrangements and audio features provide demonstrative seeding, not NIST-certified cryptographic randomness.

1. Executive Summary & Functional Scope

Digital authentication traditionally relies on pre-shared static passwords, biometric measurements, or software-based pseudorandom generators. CubeSec introduces an experimental hybrid model: physically acquiring multi-modal sensor inputs from a chaotic physical artifact—a scrambled Rubik's Cube (optical configuration across 54 color stickers) and the acoustic transients of its rotational turns—to construct a reproducible physical context-binding pipeline.

Cryptographic Integrity Statement: CubeSec is an exploratory prototype for hackathon evaluation and security research. The physical cube state and scramble audio provide demonstrative physical inputs and have not undergone NIST SP 800-90B entropy validation. SHA-256 produces a deterministic collision-resistant digest; it does not amplify or create entropy. Security-critical demo tokens are issued via the operating system's CSPRNG (Python secrets.token_urlsafe).

                                      |
[Scramble Audio Clicks]   ---> Module B: Entropy Engine (NumPy DSP)

4. Threat Model & Prototype Mitigations
Threat VectorVulnerability AnalysisCubeSec Mitigation Strategy
Predictable Physical InputCube faces can be observed or photographed.Physical digest is physical context binding, NEVER a private key.
Acoustic Replay AttackAdversary replays a recorded scramble sound.Multi-modal fusion binds 54 sticker states, acoustic telemetry, and an ephemeral salt.
Image FabricationSubmitting dark or blank images to exploit classification.Strict Laplacian variance (>= 15.0) and brightness thresholds enforce honest rejection.
Token HijackingValid demo token intercepted in transit.Strict configurable TTL expiration (60–180s) automatically purges token validity.
